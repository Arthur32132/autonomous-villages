# Проверка Autonomous Villages 0.1.1

Проверяется Minecraft Java 26.2, Fabric Loader 0.19.5, Fabric API 0.161.0+26.2 и Java 25. Мод запускается в отдельном мире выделенного Minecraft-сервера; игроки и фейковые игроки на сервере отсутствуют. Рабочие миры пользователя не изменяются.

Прогон версии **0.1.1 14 октября 2026 года, 17:42–17:45** завершился успешно: **19 серверных сценариев, 7 JUnit-тестов мода и 94 теста библиотеки, 0 ошибок**, отдельная проверка сохранности повреждённого файла и реальный графический клиент с набором модов Fabulously Optimized (3). Клиент сам создал новый мир, зарегистрировал деревню с настоящим жителем, получил его клиентскую сущность, вышел и повторно загрузил мир. Житель, активная деревня и ровно 17 алмазов в рюкзаке сохранились. Клиент завершился штатно с кодом 0.

Отчёты: [сервер](docs/validation/2026-10-14-0.1.1/server-summary.json), [клиент](docs/validation/2026-10-14-0.1.1/client-summary.json). SHA-256 основного JAR: `4d33ac874111e3c1429be99c7dae7f9075a0edf32bd2bd5b2bf3d7c95f9a6235`; библиотеки: `a30b1fe030f7746d90aaa8333776b0d6f9542e47ceb2600c23717044500ee6db`. Предыдущий успешный отчёт выделенного сервера для 0.1.0 сохранён в `docs/validation/2026-10-14/`.

Причина клиентского падения 0.1.0: у библиотеки было `environment: "server"`, поэтому Fabric исключал её из клиентского процесса, включая встроенный сервер. В 0.1.1 среда изменена на `"*"`; API и игровая логика сохранены. Проверка выполнялась на копии набора модов, с новыми настройками и новым миром, без пользовательских сохранений и настроек шейдеров. Windows Graphics Capture не удалось получить кадр; результат подтверждён проверками на клиентском/серверном потоках и журналами, визуальный кадр и видео не получены.

## Автоматические сценарии

Проверочный мод собирается отдельно командой `./gradlew.bat validationJar`. Основной JAR проверяется без изменения его содержимого. В комплект установки проверочный мод не входит.

Серверная проверка включает:

1. Выбор настоящей деревни командой, отказ при пустой территории и пересекающихся границах.
2. Сохранение UUID и типа Villager; отсутствие зарегистрированных игроков.
3. Крафт через загруженный recipe manager: расход исходных материалов и атомарный отказ неверного рецепта.
4. Общий сундук: внесение/изъятие, сохранение количества предметов, заполненный склад и запрос его расширения.
5. Физический подход, сбор зрелого урожая, подбор дропа и пересев.
6. Добыча камня, настоящий дроп и износ кирки.
7. Лестничная шахта на восемь ступеней с подбором материалов и возвратом ко входу.
8. Настоящая печь: топливо, время плавки, перенос готового железа.
9. Почти полный рюкзак: выход печи не копируется частично при одновременной загрузке топлива.
10. Перенос еды в обычный инвентарь жителя и готовность к обычному размножению.
11. Защита настоящего жителя от зомби.
12. Постройка дома из 85 частей: расход 80 структурных досок, ступени, двери, двух кроватей и факела.
13. Возвращение к ночному сну и использование новой кровати.
14. Отдельное время для обычной профессии и обновления торговли.
15. Пауза: рюкзак сохраняется, билеты загрузки снимаются.
16. Хозяйство с пустыми рюкзаками: два жителя самостоятельно заготавливают дерево, создают верстак/склад, собирают и пересевают урожай, получают хлеб без присутствия игроков.
17. Отмена текущего задания при паузе и возобновление работы.
18. Перезапуск: метаданные, настоящие жители и ровно 17 контрольных алмазов в рюкзаке без дублирования.
19. Освобождение деревни оставляет жителей живыми; активная деревня возобновляется после перезапуска. На этом запуске `pause-when-empty-seconds=1`, поэтому одновременно проверяется работа при пустом сервере с включённой автопаузой.

Дополнительный запуск подсовывает заведомо повреждённый JSON метаданных и проверяет побайтовую сохранность файла после остановки сервера. Семь JUnit-проверок покрывают границы территории, пересечения, некорректные метаданные и владение/истечение резервов рабочих целей.

## Воспроизведение

```powershell
./gradlew.bat test build validationJar
python tools/validation/run.py
./gradlew.bat clientValidationJar
python tools/client-validation/run.py
```

Требуется существующий тестовый шаблон `../navigation-fixes-validation/server` с уже принятой EULA и установленными бинарными файлами Fabric 26.2. В новый каталог копируются только бинарные файлы, библиотеки и EULA; создаётся новый мир на `127.0.0.1:25589`. Публичный доступ, RCON и онлайн-аккаунты не используются.

Результат серверного прогона — `build/validation/<дата-время>/summary.json`, журналы и контрольные суммы JAR. Клиентская проверка использует локально установленные бинарные файлы Minecraft/Fabric/Java из ModrinthApp, копирует только моды в `build/client-validation/<дата-время>/profile`, запускается без учётных данных и управляет только своим тестовым миром через API. Исходный профиль не изменяется этим скриптом. Оба проверочных мода собираются отдельно и не входят в установочный комплект. Проверены условия обычного размножения, а не гарантированное рождение ребёнка в каждом прогоне.
